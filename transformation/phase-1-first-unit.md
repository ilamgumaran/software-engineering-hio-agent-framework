# Phase 1: First Cognitive Unit (Weeks 4-10)

## Goal

Form the first cognitive unit from the pioneer group, run 3 full harmonized sprints, and generate enough evidence to justify expansion. This is where the HIO model moves from theory to practice.

---

## Weeks 4-5: Unit Formation

### Redefine Roles as Cognitive Functions

- Each pioneer maps their **primary** and **secondary** cognitive functions based on workshop self-assessment and team discussion
- No one is locked into a single function — the goal is **fluidity**, but everyone starts with a home base
- Create a visible **function coverage map** showing who can exercise which functions and where gaps exist
- Identify functions that need development — these become explicit growth goals

### Assign AI Agents

- Each person pairs with AI agents relevant to their primary functions:
  - **Builder** + **Code Co-Creator** + **Quality Analyst**
  - **Problem Framer** + **Analysis Partner** + **Architecture Explorer**
  - **Pattern Integrator** + **Analysis Partner** + **Metrics Monitor**
  - **Quality Guardian** + **Quality Analyst** + **Code Co-Creator**
- Everyone gets access to all agents — pairings are starting points, not restrictions
- Run hands-on pairing sessions to build comfort with the human-AI workflow

### Establish Working Agreements

- Define the unit's **harmonized sprint cadence** (recommend 2-week sprints)
- Adopt all 6 HIO workflows: **Sprint Kickoff**, **Daily Harmony Check**, **Sprint Outcome Review**, **Harmonization Retrospective**, **Deep Work + Collaboration**, **Exploration Time** (see [../workflows/](../workflows/))
- Set aside **10% Exploration Time** from the first sprint — this is non-negotiable
- Agree on how to handle the **expected productivity dip** — reduced scope, not longer hours

### First Sprint Kickoff

- Run the full **Sprint Kickoff** ceremony with AI-powered pre-analysis (see [../workflows/sprint-kickoff.md](../workflows/sprint-kickoff.md))
- **Analysis Partner** pre-analyzes the backlog and presents patterns to the team
- Team selects work based on cognitive function alignment, not just skill/role match
- Set explicit learning goals alongside delivery goals for this sprint

---

## Weeks 5-6: Sprint 1 (Learning Sprint)

### Focus

This is the **learning sprint** — expect lower output, focus on ceremony adoption and human-AI workflow development.

### Activities

- Run all 6 workflows for the first time with full facilitation support
- **Daily Harmony Check** replaces standup — focus on energy, blockers, and function fluidity (see [../workflows/daily-harmony-check.md](../workflows/daily-harmony-check.md))
- Each person logs their AI collaboration patterns — what works, what feels forced
- **Metrics Monitor** begins automated capture for the unit
- Coach (or external facilitator) observes every ceremony and provides feedback

### Expected Outcomes

- Ceremonies feel awkward but complete — this is normal
- Output is **15-20% below baseline** — this is the expected dip, not a failure
- At least 2-3 moments where human-AI collaboration produces unexpected value
- Team begins to recognize **identity grip** patterns in themselves and each other

### Weekly Leadership Check-In

- Share metric trends honestly — including the dip
- Highlight qualitative observations: what's changing in how people work
- Reinforce that the dip was predicted and is a sign of genuine transformation

---

## Weeks 7-8: Sprint 2 (Optimization Sprint)

### Focus

Refine workflows based on Sprint 1 retrospective. The team now knows what feels wrong — this sprint is about fixing it.

### Activities

- **Harmonization Retrospective** from Sprint 1 drives specific changes (see [../workflows/harmonization-retrospective.md](../workflows/harmonization-retrospective.md))
- Adjust ceremony timing and format based on team feedback
- Deepen AI agent usage — move from basic assistance to collaborative problem-solving
- Begin **function rotation experiments** — people try secondary functions on real work
- Start logging **emergence events** formally (see [emergence-detection.md](emergence-detection.md))

### Expected Outcomes

- Ceremonies feel more natural, team starts owning them
- Output begins recovering toward baseline
- AI task sophistication moves from Level 1 (basic assistance) toward Level 2 (collaborative)
- First documented emergence events captured

---

## Weeks 9-10: Sprint 3 (Evidence Sprint)

### Focus

Capture compelling data for the Phase 2 expansion case. This sprint needs to **prove direction**, not perfection.

### Activities

- Full measurement across all 9 metric categories with comparison to baseline
- Team self-documents their practices — what they'd tell the next unit
- **Sprint Outcome Review** with quantitative and qualitative evidence (see [../workflows/sprint-outcome-review.md](../workflows/sprint-outcome-review.md))
- Prepare the Phase 1 report: metrics, stories, learnings, recommendations
- Invite curious observers from the broader org to the Sprint 3 ceremonies

### Expected Outcomes

- Output at or slightly above baseline with measurably different quality characteristics
- DORA metrics showing **direction of improvement** (not necessarily target yet)
- Team fulfillment measurably higher than baseline
- Playbook v0.1 drafted from the team's lived experience

---

## Exit Criteria

- [ ] 3 harmonized sprints completed with all 6 workflows practiced
- [ ] DORA metrics showing direction of improvement over baseline
- [ ] Team fulfillment at **7+/10 average** on Harmony Pulse
- [ ] At least **2 documented emergence events** with clear description of how human-AI collaboration exceeded individual capability
- [ ] Practices documented in **Playbook v0.1** — ceremonies, workflows, AI agent patterns, lessons learned
- [ ] AI task sophistication at Level 2+ for majority of the team
- [ ] Weekly leadership check-ins completed with honest metric sharing
- [ ] At least 3 people from the broader org have observed ceremonies

---

## Risks in This Phase

| Risk | Trigger | Mitigation | Monitor |
|------|---------|------------|---------|
| Productivity dip exceeds 15% | Sprint velocity drops significantly | Reduce scope further, add coach support, review if workload is realistic | Sprint velocity vs baseline |
| Pioneer burnout | Fulfillment scores dropping, overtime increasing | Reduce scope, rotate ceremony facilitation, frame struggles as learning | Harmony Pulse scores, working hours |
| Identity grip blocks function fluidity | People refuse to try secondary functions | Don't force it, share stories of successful rotation, coach 1:1 | Function rotation participation rate |
| Ceremonies feel performative | Team going through motions without engagement | Adjust format based on retro feedback, let team redesign what isn't working | Retrospective feedback quality |

---

### Organization Extension Point

> **YOUR_ORG:** Adjust sprint length based on your existing cadence. If your org already runs 1-week sprints, keep that — don't change cadence AND model simultaneously. If your org has heavy on-call or interrupt-driven work, account for this in sprint capacity planning and consider how on-call rotation interacts with cognitive function assignment.
