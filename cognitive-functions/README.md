# Cognitive Functions

## The Function Composition Model

HIO (Harmonized Intelligence Orchestration) replaces fixed job titles with composable **cognitive functions** -- discrete frequencies of engagement that describe *how* a person or AI agent participates in work. Each individual holds 2-3 functions at any given time, forming their personal "frequency blend." Functions are not permanent assignments; they evolve as people grow bandwidth, shift context, or rotate through projects.

This model applies equally to humans and AI agents. An AI agent composed of **Builder + Quality Guardian + Pattern Integrator** engages with work through those three lenses, just as a human engineer might. The composition determines behavior, not a title.

---

## How Functions Differ from Roles

| Dimension | Traditional Role | Cognitive Function |
|-----------|-----------------|-------------------|
| **Exclusivity** | One person owns a role; others must not overlap | Multiple people can hold the same function simultaneously |
| **Permanence** | Roles persist until a reorg event | Functions shift as bandwidth expands or project needs change |
| **Growth path** | Promotion to a different role (IC to manager) | Bandwidth expansion adds adjacent functions without losing existing ones |
| **AI compatibility** | AI "replaces" or "augments" a role | AI agents compose the same functions as humans, enabling true collaboration |
| **Identity relationship** | "I am a Senior Engineer" (identity grip) | "I'm currently operating in Builder + Pattern Integrator" (fluid engagement) |
| **Overlap handling** | Turf wars and RACI matrices | Natural resonance -- whoever activates the function engages |
| **Team composition** | Headcount per role | Function coverage across the team, with deliberate gaps identified |

## Bandwidth Expansion

Cognitive functions grow through a four-phase model. Each phase builds on the previous one, and individuals move through them at different speeds depending on context, support, and deliberate practice.

### Phase 1: Depth with Awareness
Operate fluently in your primary function (1-2 functions). Build enough mastery that you can engage without constant deliberation. Simultaneously, develop awareness of adjacent functions through observation and collaboration.

### Phase 2: Adjacent Engagement
Begin activating a neighboring function in low-stakes situations. A **Builder** might start engaging as a **Quality Guardian** during code review, or a **Problem Framer** might experiment with **Pattern Integrator** thinking during retrospectives.

### Phase 3: Multi-Frequency Fluency
Hold 2-3 functions with confidence, switching between them based on context rather than assignment. At this stage, your function blend becomes a recognizable contribution pattern that the team relies on.

### Phase 4: Pattern Integration
Transcend individual functions to see how they interact across the team. Help others discover and develop their function blends. Contribute to the evolution of function definitions themselves.

## Adding a New Function

The set of cognitive functions is not fixed. As the organization encounters new challenges, new frequencies of engagement may emerge. Follow these steps to propose and integrate a new function:

1. **Identify the gap.** Observe recurring situations where no existing function adequately describes the engagement needed. Document 3-5 concrete examples.

2. **Draft the function file.** Follow the standard template used by all function files in this directory: Identity, Activation Triggers, Core Behaviors, Collaboration Patterns, Growth Path, Anti-Patterns, and Example.

3. **Map collaboration patterns.** Define how the new function interacts with each of the existing 10 functions. This forces clarity about what the function is and is not.

4. **Validate through composition.** Identify at least two real (human or AI) compositions that include the new function. If it cannot compose naturally with existing functions, it may be a refinement of an existing function rather than a new one.

5. **Integrate into the framework.** Add the function to the master table in this README, update the collaboration patterns in all existing function files, and propose initial growth path stages.

> **Organization Extension Point:** Your organization may discover functions specific to your domain -- for example, a "Compliance Navigator" in regulated industries or a "Community Cultivator" in open-source organizations. Use the process above to formalize them.
